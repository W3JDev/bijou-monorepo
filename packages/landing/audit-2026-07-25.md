## **New** findings (2026-07-25, not in any prior audit)

### N1. `tsc --noEmit` fails on 30+ errors — the build is currently broken

**Evidence:** `npx tsc --noEmit` output (truncated; full list 30+ lines):

```
App.tsx(95,12): error TS2741: Property 'onOpenModal' is missing in type '{}' but required in type 'HowItWorksProps'.
App.tsx(97,12): error TS2741: Property 'onOpenModal' is missing in type '{}' but required in type 'PlaybooksProps'.
components/ComparisonTable.tsx(375,43): error TS2532: Object is possibly 'undefined'.
components/Features.tsx(424,56): error TS18048: 'c' is possibly 'undefined'.  (×4)
components/Hero.tsx(66,15): error TS2322: ... Framer Motion Variants type mismatch.  (×5)
components/LanguageSwitcher.tsx(33,53): error TS18048: 'currentLanguage' is possibly 'undefined'.  (×3)
components/OnboardingModal.tsx(58,13): error TS7030: Not all code paths return a value.
components/OnboardingModal.tsx(395,25): error TS2345: ... 'industry' missing from state type.
components/OnboardingModal.tsx(757-766, 5 errors): TS2367: comparison '"error" | "idle"' and '"loading"' have no overlap.
components/Playbooks.tsx(98-126, 6 errors): error TS18048: 'activeTab' is possibly 'undefined'.
```

**Why it matters.** `tsc --noEmit` is the only automated check this repo runs. If it fails, the type guarantee is gone; the build (`npm run build`) is also likely to fail at the Vite stage if it depends on TS. New contributors will see red squiggles in their editor and assume the project is unmaintained. None of the prior audits re-ran `tsc` against the current tree.

**Action.** S1 (this turn) — fix every error. This is mechanical and pure-local.

### N2. `public/manifest.json:42` introduces a THIRD "trial length" claim

**Evidence:** `public/manifest.json:42` — `"description": "Sign up for your 7-day free trial"`. The README, i18n keys, FinalCTA, InfoModal, FAQ, and `api/*.js` say "30-day money-back guarantee". `OnboardingModal.tsx:434` and the slide-deck endpoints say "14 days free".

**Why it matters.** A PWA-install shortcut shown in the OS app drawer is now a third, contradicting promise. The 2026-07-20 audit flagged the 14/30 drift; the 7/30 drift is new and the user's home screen will keep showing it.

**Action.** S1 — change `manifest.json:42` to "Sign up — 30-day money-back". Reconcile the remaining 14/30 drift in S2 (single source of truth in i18n).

### N3. `.env` has a typo in the spelling of `CUSTOME` (should be `CUSTOM`)

**Evidence:** `.env:28` `CUSTOME_API_KEY`, `.env:32` `CUSTOME_API_ENDOINT_INTERFACE_PROVIDER`, `.env:33` `CUSTOME_API_ENDOINT_INTERFACE_PROVIDER_DOCS`. The "typo" comment at `.env:30` says the spelling was fixed on 2026-07-20, but the `CUSTOME_*` (with the `E`) spelling remains in 3 keys.

**Why it matters.** Cosmetically ugly. The runtime works (same string in code and env). Adds cognitive load for future devs.

**Action.** S2 — full rename in a single commit + .env.example.

### N4. `OnboardingModal.tsx` is 816 lines (was 810 in audit)

**Evidence:** `wc -l components/OnboardingModal.tsx` = 816. Six lines of growth since 2026-07-20.

**Action.** S2. The god-file remains.

### N5. `.gitignore:78-79` comment explains a "weird" decision

**Evidence:** `.gitignore:78-79` —

```
# NOTE: public/brand/ is intentionally tracked — Vercel must serve these assets
# public/brand/logo.png and qr.png are referenced by email templates & the landing page
```

**Why it matters.** Fine — this is a justified decision, and the orphan PNGs are gone. Worth recording so a future cleanup doesn't re-delete the 3 remaining files.

**Action.** None.

### N6. `.env` has `RESEND_*_SEND_EMAILS` and `IMPROVMX_*_RECEIVE_EMAILS` per-domain — likely misconfigured

**Evidence:** `.env:87-138` (4 Resend domains, 4 ImprovMX domains, each with their own `_SEND_EMAILS` / `_RECEIVE_EMAILS` flag).

**Why it matters.** The marketing-site `api/*.js` only uses `RESEND_API_KEY` (`.env:57`). The 4 per-domain keys are referenced by the production backend (`w3j-bijou-ai-main`). They live in this repo's `.env` because the founder's local dev setup pulls one `.env` across both repos via a symlink or shared dir. **This is a separation-of-concerns smell, not a security issue today.** But if this `.env` ever leaks (e.g. via the GitHub push-protection audit), all 4 Resend domains are exposed in one file.

**Action.** S2 — create a `.env.example` that omits the per-domain Resend/ImprovMX keys (they belong to the backend repo's `.env`). Add a one-line README note in `scripts/` pointing to the backend repo for those keys.
