## Cron chain design — what to know

**Time math (Asia/Kuala_Lumpur):**
- 5am–8pm = **sleep** = autonomous crons run (lead-monitor, pricing-drift, static-audit, cost-watchdog, prod-health)
- 8pm–5am = **work** = collaboration crons (daily-brief, EOD, task check-in, LinkedIn drafts)

**Gate discipline (no spam):**
- All crons are silent 99% of the time
- They only fire alerts on threshold breach
- They write drafts to `outbox/`, never auto-send
- `<mavis-progress>` tags mark silent ticks
- Repeat-failure detection prevents alert storms

**Self-cleanup rules (built into each cron's prompt):**
- `bijou-eod` deletes the old `hermes-eod` on first run (already done manually)
- `mercury-z-recheck` (existing) has TTL until 2026-07-24
- `bijou-cost-watchdog` suppresses repeat alerts within 4h
- `bijou-prod-health` suppresses repeat-failure alerts

**Cross-cron coordination:**
- `bijou-daily-brief` reads from the outputs of all the other crons
- `bijou-eod` summarizes the git log + outbox/ folder
- The crons don't talk to each other directly (no message bus), they read from a shared filesystem
